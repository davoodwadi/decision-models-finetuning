# Best checkpoint evaluation on held-out test datasets

One notebook per model (`04-test-best-800m`, `04-test-best-4b`, `04-test-best-9b`) runs locally on the training runs pulled from Rorqual and Nibi. Each notebook loads the base model once, then for every finished run in its runs folders (`RUNS_DIR`, or `RUNS_DIRS` for 9B) loads `checkpoints/best.pt` (LoRA and pointer head, selected during training by `kriner2026/beta_mse`) and evaluates it on the test datasets listed in `TEST_DATASETS` using the same fused population validation used during training.

**Test datasets.** All three notebooks evaluate `grummon2025`, `covid` (Kreps et al. 2020 vaccine conjoint, 1,971 respondents, 9,855 tasks, 11 Table 3 terms), `kantorowicz2026` (Kantorowicz-Reznichenko et al. 2026 consumer rights conjoint, 2,235 US respondents, 26,823 tasks across computers and laundry machines, 38 AMCEs), and `magistro2025` (Magistro et al. 2025 AI & offshoring smartphone conjoint, 5,525 US and Canadian respondents, 21,005 tasks across four country × arm regressions, 32 AMCEs). None of these datasets is trained on, and none selects the checkpoint. Grummon 2025 at `best.pt` also appears in each run's `best_validation.csv` from the end of training, and these notebooks compute it again from `best.pt` with the same validator alongside the other test datasets.

**Outputs and caching.** Row 1 (the untrained model) is not tested here: it belongs to the sim-respondents paper, and this paper reads its results from `code/papers/sim-respondents/runs-rorqual/<model>/row1_base_untrained/test_best/` (the same holds for Rows 2b, 3 and 5). Every finished run writes its results to `<runs folder>/<model>/<run>/test_best/`, producing `metrics.csv` (one row per test dataset with `kl_loss`, `beta_mse`, `beta_mae`, `beta_mape_pct`, `spearman_rho`, and timings), `betas.csv` (model and human population betas per term, stacked with a `validator` column), and `test.json` (notebook, model, paper row, checkpoint step, best metric and value, and test datasets). Unfinished runs are skipped, and finished runs reuse verified results from `test_best/` whenever `checkpoint_step` and `MODEL_KEY` match so adding a new dataset evaluates only the missing dataset(s) before merging and saving atomically.

**Runs folders and pulling.** The 0.8B and 4B runs live in `runs-rorqual/<model>/`, whereas 9B spans `runs-rorqual/kev-9b/` for Rows 2 and 2 ablation (trained on Rorqual) and `runs-nibi/kev-9b/` for Rows 4 and 4 ablation (trained on Nibi). Finding the same run name in both 9B folders stops the notebook because it would represent duplicate copies of the same regime. Before running, execute `sync/pull-rorqual-runs.sh` and, for 9B, `sync/pull-nibi-runs.sh` from the paper folder to copy each run's files and `checkpoints/best.pt` (not `last.pt`) into `runs-rorqual/` and `runs-nibi/`. Later pulls leave `test_best/` untouched because it exists only locally.
