# ANES 2024 Time Series Study layout and pipeline notes

## Directory contents and authoritative files

The folder contains the May 2026 Full Release of the ANES 2024 Time Series Study alongside supplemental instruments and auxiliary files. Only two files are required for the persona and question pipeline. The primary archive [anes_timeseries_2024_stata_20260519.zip](./anes_timeseries_2024_stata_20260519.zip) holds both the complete Stata microdata file (`anes_timeseries_2024_stata_20260519.dta`, 5,521 respondents by 1,738 variables with 1,690 embedded value label sets) and the 674-page official documentation (`anes_timeseries_2024_userguidecodebook_20260519.pdf`). The companion document [anes_timeseries_2024_questionnaire_20240808.pdf](./anes_timeseries_2024_questionnaire_20240808.pdf) (481 pages, dated August 8, 2025) contains the full Pre-Election and Post-Election verbatim survey questionnaires with explicit `Release Variable(s)` links back to Stata column names.

The remaining files in the directory are optional artifacts that the exporter does not need. The archive [anes_timeseries_2024_stata_VoterValidation.zip](./anes_timeseries_2024_stata_VoterValidation.zip) stores external voter-file validation flags, [anes_timeseries_2024_questiontimings_csv_20251121.zip](./anes_timeseries_2024_questiontimings_csv_20251121.zip) stores item-level response timings, and [anes_timeseries_2024_redactedopenends_excel_20250923.xlsx](./anes_timeseries_2024_redactedopenends_excel_20250923.xlsx) stores redacted free-text answers. The additional PDFs ([anes_timeseries_2024_CAPI_screener.pdf](./anes_timeseries_2024_CAPI_screener.pdf), [anes_timeseries_2024_web_screenerSPS.pdf](./anes_timeseries_2024_web_screenerSPS.pdf), [anes_timeseries_2024_questionnaire_papi_20241106.pdf](./anes_timeseries_2024_questionnaire_papi_20241106.pdf), [anes_timeseries_2024_questionnaire_post_papi_20250220.pdf](./anes_timeseries_2024_questionnaire_post_papi_20250220.pdf), and [anes_timeseries_2024_questionnaire_sps_20241106.pdf](./anes_timeseries_2024_questionnaire_sps_20241106.pdf)) document household screeners and paper or Spanish instruments and are needed only when inspecting paper-mode wording discrepancies.

## Dataset layout and sample structure

Each row in `anes_timeseries_2024_stata_20260519.dta` is one respondent identified by `V240001` (2024 Time Series Case ID, `N = 5,521`). The sample combines three frames tracked in `V240003`, namely the 2016 to 2024 returning panel (`n = 2,171`), the fresh Web cross-section (`n = 2,308`), and the fresh Face-to-Face cross-section (`n = 1,042`). Completion status is stored in `V240002c`, with 4,964 respondents completing both the Pre-Election and Post-Election interviews and 557 completing the Pre-Election interview only. Pre-Election interview mode (`V240002a`) splits across Web (`n = 4,234`), Face-to-Face (`n = 966`), Paper PAPI (`n = 245`), and Phone (`n = 76`). Post-Election mode (`V240002b`) adds Video (`n = 344`) alongside Web (`n = 3,839`), Face-to-Face (`n = 354`), Phone (`n = 227`), and Paper PAPI (`n = 200`).

A critical structural detail is the 245-respondent Paper (PAPI) subsample. Paper questionnaires used shortened wording or fewer response bins on several items, so main Web and Face-to-Face variables carry `-1. Inapplicable` for those 245 respondents while separate `PAPER:` columns (`34` variables total) store the paper-only responses. Whenever ANES publishes a harmonized summary column ending in `x` (e.g., `V241465x` for 5-category education or `V241567x` for 6-category income), that summary column merges both main and paper respondents into one unified scale across all 5,521 rows.

Columns in the Stata file are organized cleanly by prefix into seven functional blocks.

| Prefix | Column count | Role in dataset |
| --- | --- | --- |
| `V240xxx` | 37 | Case ID (`V240001`), interview modes (`V240002a`, `V240002b`), completion status (`V240002c`), sample type (`V240003`), and raked weights, PSUs, and strata (`V240101a` through `V240108d`) |
| `V241xxx` | 808 | Pre-Election survey items, respondent demographics, political orientations, and harmonized `x` summary variables |
| `V242xxx` | 615 | Post-Election survey items, follow-up attitudes, feeling thermometers, CSES6 module (`72` items), and GSS replication module (`14` items) |
| `V243xxx` | 30 | Geographic and sample frame variables, including state postal abbreviation (`V243001`), Census region (`V243007`), and restricted county or tract placeholders |
| `V244xxx` | 227 | Experimental randomization and item-order indicators (`RAND:`), useful for checking option-order balancing rather than modeling as survey questions |
| `V245xxx` | 18 | Interviewer demographic descriptors (`IWR DESCR:`) |
| Other | 3 | Release tag (`version`) and longitudinal link IDs (`V160001_orig`, `V200001`) |

All ANES missing values are encoded as negative integers rather than Stata extended missing values, so reading the file with `pandas.read_stata(..., convert_categoricals=False)` preserves every code explicitly. Standard missing codes are `-9` (Refused), `-8` (Don't know), `-7` (Insufficient partial, interview deleted), `-6` (No post-election interview), `-5` (Break off, sufficient partial), `-4` (Error), `-2` (Missing or unable to code in summary), and `-1` (Inapplicable due to skip logic or mode). Any value strictly below zero must be excluded from valid response options unless an explicit audit decision says otherwise.

## Where persona attributes should come from

All respondent persona attributes come directly from `anes_timeseries_2024_stata_20260519.dta`, joined on `V240001` as `CASEID`, with `country` fixed to `United States`. Prefer the harmonized summary columns (`x` suffix) whenever available so that all 5,521 respondents, including the 245 paper-mode respondents, receive non-missing values on a consistent scale before passing through `code/data/persona_spec.yaml`.

| Canonical `persona_spec.yaml` attribute | Primary ANES 2024 column | Valid `n` (of 5,521) | Notes and caveats for mapping |
| --- | --- | --- | --- |
| `country` | Constant (`United States`) | 5,521 | Entire study is a U.S. national sample |
| `age` | `V241458x` | 5,242 | Election Day age, top-coded at `80` (80 or older); `V241457` holds paper age (`n = 230`) if needed for missing birthdates |
| `gender` | `V241550` (fallback/detail: `V241551`) | 5,475 | `V241550` is sex (`1` Male, `2` Female) across all modes; `V241551` adds Nonbinary (`n = 46`) and Something else (`n = 18`) for non-PAPI modes (`n = 5,234`) |
| `region` | `V243007` | 5,521 | Exact 4-category U.S. Census region (`1` Northeast, `2` Midwest, `3` South, `4` West) |
| `state` | `V243001` | 5,521 | Two-letter sample state postal abbreviation (e.g., `CA`, `TX`, `FL`) |
| `education` | `V241465x` (fine detail: `V241463`) | 5,465 | `V241465x` harmonizes Web, FTF, and PAPI into 5 standard education levels; `V241463` has 16 fine levels for non-PAPI only (`n = 5,260`) |
| `family_income` | `V241567x` (fine detail: `V241566x`) | 5,200 | `V241567x` harmonizes all modes into 6 household income brackets; `V241566x` has 28 fine brackets for non-PAPI only (`n = 4,965`) |
| `race` | `V241501x` | 5,454 | 6-category race/ethnicity summary (White, Black, Hispanic, Asian/NHPI, Native American/Other, Multiple races) |
| `hispanic` | `V241499` | 5,493 | Binary Hispanic or Latino self-identification (`1` Yes, `2` No) |
| `religion` | `V241445x` (or `V241422` + `V242461`) | 5,200 | `V241445x` gives 9 major religious traditions (Mainline, Evangelical, Black Protestant, Catholic, Jewish, Other, Not religious) for non-PAPI; `V241422` (`n = 5,226`) and post-election `V242461` (`n = 182`, PAPI) can recover paper respondents |
| `religious_attendance` | `V241439` + `V241440` | 5,242 | Two-step skip structure: `V241439 = 2` (No) means never attends, while `V241439 = 1` (Yes) branches to 5-level frequency in `V241440` |

Additional shared `persona_spec.yaml` attributes also appear in the Pre-Election and Post-Election blocks if needed later, including household union membership (`V241497` and `V241498a`), number of children under 18 in the household (`V241521`), and subjective social class (`V242337`). Note that `V242341` (`urban_rural`) and `V242337` (`social_class`) are Post-Election items and are therefore missing (`-6`) for the 557 Pre-Election-only respondents.

## Where questions should come from

Candidate attitudinal and opinion questions live in the Pre-Election (`V241xxx`, 808 columns) and Post-Election (`V242xxx`, 615 columns) blocks, totaling 1,423 columns before filtering. A clean catalog builder should exclude non-question and unusable columns first, specifically restricted redacted placeholders (`80` columns starting with `RESTRICTED:`), paper-only mode duplicates (`34` columns containing `PAPER:`), interviewer observations (`64` columns with `IWR` or `INTERVIEWER:`), open-ended text fields (`33` columns with `[text]` or `{SPECIFY}`), persona demographic variables already placed in the respondent profile, and administrative consent or language items.

Two ANES question formats require explicit audit rules during catalog construction. First, ANES frequently asks branched two-part items (e.g., `V241147` Approve or disapprove, followed by `V241148` Strongly or not strongly) and then publishes a combined `x` summary column (`V241149x`, 116 such summary variables across Pre and Post). Keeping the harmonized `x` summary variable while excluding its two constituent branch columns avoids duplicate items and eliminates conditional skip bias, provided the prompt text presents the unified scale cleanly (or vice versa, keeping only the unconditional root item when the follow-up stem is hard to combine cleanly). Second, ANES includes 58 feeling thermometers (`0` to `100` numeric ratings) and a 14-item Post-Election GSS replication battery (`V242608` through `V242621`, labeled `POST: GSS:`). Feeling thermometers are continuous ratings rather than discrete choice options and should be excluded from discrete choice and score tasks unless binned explicitly. The 14 `POST: GSS:` items (e.g., `V242614` happiness and `V242617` through `V242620` institutional confidence) should be tagged during audit because several overlap in wording with ISSP and WVS Wave 7 training items.

Verbatim question wording should come from [anes_timeseries_2024_questionnaire_20240808.pdf](./anes_timeseries_2024_questionnaire_20240808.pdf) and `anes_timeseries_2024_userguidecodebook_20260519.pdf`, never from the truncated 80-character Stata variable labels alone. Every question block in the questionnaire PDF prints a `Release Variable(s)` line (e.g., `Release Variable(s) V241147`) alongside the exact `Survey Question`, `Universe`, and `Display Spec`, while the codebook PDF prints `Question`, `Survey Question(s)`, `Universe`, and `Value Labels` under each `V24xxxx` header. Parsing both PDFs lets us join verbatim stems deterministically to `V24xxxx` columns and inspect conditional universes so skipped-subsample items can be flagged in `question_audit.csv`. Dynamic questionnaire fill placeholders (e.g., `^presnow_name` for Joe Biden or randomized candidate name tokens) appear in raw questionnaire text and must be resolved to their 2024 realizations and verified in the Audit UI before export.

## Where response options and answers should come from

Respondent answers and authoritative option codes come directly from `anes_timeseries_2024_stata_20260519.dta`. Reading the Stata file via `pandas.read_stata(..., iterator=True)` exposes `value_labels()` and the variable-to-label-set mapping (`_varlist` and `_lbllist`), which provides the exact integer code and text label for every response option on all 1,690 labeled variables.

Before exporting options into the audit catalog, the parser should strip numeric prefixes from Stata value labels (e.g., `"1. Approve"` becomes `"Approve"`), filter out all negative missing-value codes (`code < 0`), and verify that every remaining non-negative code matches the numbered choices printed in [anes_timeseries_2024_questionnaire_20240808.pdf](./anes_timeseries_2024_questionnaire_20240808.pdf). Special non-substantive positive codes (such as `99. Haven't thought much about this` on 7-point policy scales or volunteered `{VOL}` categories) should be surfaced in `question_audit.csv` so they can be reviewed and dropped via `drop_options` when appropriate, following the same audit workflow used for ISSP and WVS Wave 7.
